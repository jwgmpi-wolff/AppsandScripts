# Deploy To Another Tenant

This workflow creates a fresh, independent deployment from GitHub in one target tenant. It does not enable cross-tenant access. Do not copy credentials, registrations, app IDs, API URLs, or package identifiers from an existing deployment.

## Required Copilot Entitlement

The target tenant must have Microsoft 365 Copilot Chat enabled before deployment. At least one designated deployment/test user must be able to open `https://m365.cloud.microsoft/chat` without being redirected to `/chat/blocked`.

Treat a blocked Copilot Chat page as a failed prerequisite. Have a Microsoft 365 administrator enable Copilot Chat or assign the required entitlement, then verify access before creating the tenant's Entra app, OAuth registration, API resources, or agent package.

For an agent-driven deployment, run `/deploy-finops-copilot` in VS Code GitHub Copilot Chat. The [one-request prompt guide](COPILOT_ONE_REQUEST_DEPLOYMENT_PROMPT.md) includes parameters and a copy/paste alternative.

## Values That Change Per Tenant

| Value | Created or supplied by |
| --- | --- |
| Tenant ID | Authenticated Azure administrator; auto-detected by the setup script |
| Entra client ID and secret | Target tenant administrator |
| Developer Portal OAuth registration ID | Target tenant administrator |
| Teams app ID | Auto-generated by the setup script |
| FinOps API URL | Target environment owner |
| Publisher name, URLs, and contact | Target organization |

The client secret is never passed to the setup script. Enter it only in the tenant's Developer Portal OAuth registration and retain it in a secure vault.

## Fast Path

1. Verify the target tenant has Copilot Chat enabled and the designated test user can open Microsoft 365 Copilot Chat.
2. In the target tenant, create fresh Entra and Developer Portal OAuth registrations described in [the full runbook](../finops-copilot-agent/DEPLOYMENT.md).
3. Authenticate both CLIs to that same target tenant:

   ```powershell
   az login --tenant <target-tenant-id> --use-device-code --allow-no-subscriptions
   atk auth logout m365
   atk auth login m365 --tenant <target-tenant-id>
   ```

4. From `finops-copilot-agent`, generate and validate a new package:

   ```powershell
   ./setup-tenant.ps1 `
     -ApiBaseUrl https://<finops-api-host> `
     -EntraClientId <entra-client-id> `
     -OAuthRegistrationId <oauth-registration-id> `
     -PublisherName "<organization-name>" `
     -ContactEmail <support-email>
   ```

5. Publish automatically by adding `-Publish`, or upload `appPackage/build/appPackage.dev.zip` in Teams Admin Center.
6. Assign the app to users or groups and add it from **Built by your org** in Microsoft 365 Copilot.

## Scope And Context

The package configuration determines which tenant performs OAuth. It does not hardcode which Azure subscriptions can be read.

At runtime, each user signs in and supplies tenant/subscription context. The API uses that delegated token, and Azure RBAC limits results to resources the user can access. To change business scope, change the requested tenant/subscription filters or the user's RBAC; no package rebuild is needed. To change the OAuth tenant, client, API URL, or publisher, rerun setup and republish.

For another tenant, start a separate fresh deployment with new registrations and identifiers. No access, identity, or credential is shared between tenant deployments.
